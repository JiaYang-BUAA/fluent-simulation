# 运行、调度与恢复

按任务用相应部分：只审查结果无需启动 Fluent；只讨论监控无需创建定时任务。

## 运行在哪台机器、通过什么接口

- 确认计算主机、Fluent/PyFluent 版本、许可证、可写目录及归属；脚本路径按实际执行主机解释。迁移时核对已关闭文件的大小/哈希，在新环境读回；文件传输成功不能证明旧环境或绝对路径仍可用。
- 先发现本次暴露的 MCP 工具及参数。若有 `session_status`、`solver_status`，先读状态；启动与接入已有会话分开。只控制与本作业身份一致的会话。按实际对象枚举区域、查询 API、合法值；变更后读回关键材料、模型、边界、单位和监测面。脚本静态检查通过后仍要验证实际效果。
- 无匹配 MCP 时，用该版本已验证的 PyFluent 或 Journal；新版本、脚本或批次先用代表性算例短跑，验证网格导入、真实迭代推进、指标提取和保存重读。已完成的同条件验证可复用。封装脚本须等待实际求解及保存结束；禁止把启动器返回、SSH 断开、作业退出码或文件出现当作验收。

## 资源与并行

1. 列出每个作业在哪个阶段占用多少核、峰值内存、磁盘和许可证；用 GPU 时核实该模型支持 GPU 及**单卡**可用显存。估算包含网格构建、求解、保存/后处理和检查点增长。实测同型作业优于按单元数外推；记录依据、主机/核数、耗时区间及不确定项。
2. 提交前核实共享主机：多次采样整机 CPU 与现有进程的 CPU 时间增量，读可用内存、输出卷余量、其他已运行/已预留任务及许可证占用。MPI 进程数、启动参数与瞬时空闲均不能直接换算为可用核数。核对峰值重叠和余量，资源不明/冲突时先暂停受影响的新提交，给出降并发、换机或等待的选择。
3. 有容量监视器或作业调度器时，按站点配置读取带时间戳的节点状态、公告和资源预留；用本作业的核数、峰值内存及单卡显存需求作比较。临提交再查。没有这类服务时，使用获准的主机只读指标；某次采样显示空闲，不代表已为本任务预留资源。
4. 标清依赖：单次求解内部多核、多个独立算例并发、并行准备脚本是不同的资源安排。共用一个 Fluent 会话的写操作串行；调流量、从上一状态续算、依赖审查结果的下一阶段串行。已冻结输入的独立算例可并行，分别使用会话、日志、临时与结果目录，已落盘并关闭的结果可与下批求解并行后处理。最大并发由各阶段**重叠**资源和依赖决定，总工期按实际批次/依赖链估算。
5. 授权批次中，代表性作业通过后，资源释放且依赖满足即可派发后继；先比对当前作业、会话、队列/等待器和输出目录以免重复。若共用模板或物性有错，暂停所有受影响的新提交；单例问题仅隔离该例。算例过多或反复修复仍无可验收结果时，报告累计成本和改变路线的选项。

## 监控与收尾

- 长作业开算方案中提供“是否建立定时监控”、预计间隔、通知与停止条件；已表态则沿用。需要时查当前自动化工具与已有任务，优先更新**同一监控 ID**，不新建重复任务。短试算可直接在当前任务看完；需跨轮值守、用户已选择定时监控且宿主支持时，按当前工具契约优先绑定本任务的 heartbeat。未经请求不另建独立定时作业。创建监控不等于授权增加工况或更改物理模型。
- 每次以**主机、运行目录、作业标识和检查点**定位，查看新日志、真实迭代/物理时间、工程监测量、资源趋势和写盘情况。稳定长算可拉长间隔；启动、接近阶段切换或出现异常时缩短。根据剩余时间和工具实际支持的调度粒度更新同一任务并回读；不支持改频则保留支持的间隔并说明。若用户指定固定间隔则遵从。稳态 ETA 参考每步耗时及收敛趋势，难判断就给下次复核时刻；瞬态用剩余物理时间及实测推进速度。只有实质状态变化、失败或需决策时通知。短阶段的衔接用计算端已有批处理/队列，不等待小时级心跳。
- 单例失败先分层：求解发散、报告接口错误、SSH 断线、磁盘/许可证异常分别诊断。连接丢失先查原生作业是否还活着；报告失败优先在同一已保存场上复取指标。守恒异常先核对控制体、符号、边界/影壁所属单元区，再决定是否重算。保留失败材料，给每次恢复设限。
- 续算核对 case/data 配对、工况与模型、真实迭代或物理时间、前驱检查点完整性；使用新输出目录，记录续算起点、追加量和数值改动。默认不重新初始化；若改变了物理条件，另立分支。资源紧张先暂停新提交、尽可能保存检查点；用户要求停止时仅处置指定主机的本任务，先停后继启动器，再核实求解进程、会话、许可证和检查点状态。
- 全批终态按清单核对：每例有通过/未通过/中断及原因，必要的重读、验收和交付完成。停用该监控，回读状态确认已停用，发一次最终结论。停用监控与终止求解是两种操作。等待用户决定且无可继续事项时保留检查点、通知一次；不要靠不停轮询或重算等待一个“通过”。
